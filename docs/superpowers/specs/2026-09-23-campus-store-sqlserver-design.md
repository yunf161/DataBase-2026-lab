# 校园小卖部进销存数据库设计

## 目标与范围

以 `要求.docx` 和 `要求.md` 的 10 张核心表为业务依据，使用已选定的本机 SQL Server Express 实现 `CampusStoreDB`。包含分类、商品、供应商、员工、库存、采购单及明细、销售单及明细、库存流水；包含当前库存、销售明细、每日销售三个视图，以及采购入库和销售结算两个事务存储过程。会员功能留作后续扩展。

## 结构

使用 SQL Server 的 `IDENTITY` 主键、`nvarchar` 中文字段、`datetime2` 时间、`decimal` 金额、持久化计算列和 `CHECK`/外键/唯一约束。商品现价与销售历史成交价分别存放。商品库存单独存放，商品建档时同步创建零库存记录。订单从 `DRAFT` 创建，明细仅能在草稿阶段修改；确认过程计算总额、改变库存、写流水和状态，全部在同一个事务中完成。销售结算锁定库存行后检查数量，阻止负库存；过程锁定订单以避免重复确认，状态保护触发器阻止已确认订单退回草稿。流水保存变动前后数量和业务单号。退货过程不在首版范围，销售状态暂不开放 `REFUNDED`。

## 文件和执行

- `sql/01_create_campus_store_database.sql`：建库、10 张表、索引与视图，并在商品建档时建立零库存。
- `sql/02_business_procedures.sql`：采购入库和销售结算过程，及订单状态和草稿明细保护触发器。
- `sql/03_sample_data.sql`：少量示例基础数据及演示订单。
- `sql/04_verify.sql`：验证数据库、核心表、视图和过程是否存在。
- `sql/05_business_verify.sql`：在一次性数据库验证金额、库存、流水、重复确认、库存不足、状态回退与历史成交价。
- `tests/Verify-CampusStore.ps1`：创建一次性测试数据库并运行 SQL 验证，随后删除测试库。
- `README.md`：实例、执行顺序和演示查询。

## 验收

在本机 `SQLEXPRESS` 使用 `sqlcmd -b` 执行 01、02、04、03，然后运行隔离验证脚本；查询确认正式库中有 10 张表、3 个视图、2 个过程、5 条触发器。再次运行建库脚本会提示数据库已存在，不删除旧数据。
