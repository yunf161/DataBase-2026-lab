# 第 1 周 小卖部业务边界与角色

## 场景与目标

校园小卖部售卖饮料和日用品。店员需要知道商品现价、当前库存、低库存商品、每次采购及销售金额，以及库存为什么变化。因此数据库保存商品、供应商、员工、订单、订单明细、库存和库存流水，而不是把所有信息写进一张表。

## 角色与职责

| 经营角色 | 主要工作 | 对应数据库操作 |
| --- | --- | --- |
| 管理员 `ADMIN` | 维护分类、商品、供应商和员工资料，查看经营统计 | 管理基础资料，查询统计视图 |
| 采购员 `PURCHASER` | 选择供应商、填写采购草稿、核对到货并确认入库 | 新增采购单与明细，执行 `ConfirmPurchase` |
| 收银员 `CASHIER` | 查询商品与库存、填写销售草稿并结算 | 新增销售单与明细，执行 `CompleteSale` |

`Employee.RoleName` 记录“谁做了业务”，第 4 周的 SQL Server 数据库角色控制“账号能执行什么”。二者用途不同。

## 业务流程

采购：供应商供货 → 采购员建立 `DRAFT` 采购单 → 添加商品、数量和当次进价 → 核对到货 → 确认入库。确认过程在同一事务中计算总额、增加库存、记录库存流水，并把状态改为 `RECEIVED`。

销售：收银员查看商品与库存 → 建立 `DRAFT` 销售单 → 添加商品、数量和成交单价 → 选择支付方式与优惠 → 结算。结算过程在同一事务中检查库存、计算实付金额、扣减库存、记录流水，并把状态改为 `COMPLETED`。库存不足时整单回滚。

商品建档时，系统自动建立数量为 0 的库存记录；历史销售明细保存成交价，后续修改商品现价不会改变旧订单。

## 数据边界

**本版进入数据库：**分类、商品与条码、供应商、员工、库存、采购和销售的订单头与明细、库存流水、订单状态及金额。付款方式只记录种类，不存支付账号。

**暂不进入数据库：**会员积分、支付平台交易流水、员工登录密码、退货处理、盘点调整和多门店库存。首版没有这些完整业务流程，因此也不应手动把销售单改成“已退货”。

## 可展示的业务问题

- 哪些商品低于最低库存？查询 `v_current_inventory`。
- 今天销售了多少、优惠多少？查询 `v_daily_sales`。
- 某次采购或销售为什么改变库存？按业务单号查 `InventoryLog`。
- 某件商品改价以后旧订单为何仍显示旧价格？比较 `Product.SalePrice` 与 `SaleItem.UnitPrice`。
