## 合理设计与保留理由

- **独立的订单头/明细和独立明细主码**：可表示一张单多商品，数量与当次价格属于交易行；即便第六周允许重复商品行，已有明细 ID 仍能稳定标识记录。
- **`SKU`、业务单号、供应商编号、员工编号的非空唯一约束**：既方便业务查询，也使系统 ID 与可读业务标识分工清楚。`Barcode` 可空，按非空唯一约束保留，不误称为完整候选码。
- **库存当前值与流水分离**：查询现存量快捷，流水保留变化过程；采购和销售过程在事务中同时更新两者。
- **草稿与完成状态分离**：录单过程中允许暂时缺明细；结算时才强制完整、核算金额和库存。ER 图按全状态展示 `0..N`，在规则表注明完成态的 `1..N`。
- **分类自关联和非空商品分类 FK**：树形分类可复用，环检测触发器避免错误层级。现阶段不需要另建分类层级实体。

迁移顺序建议：先明确会员和重复明细的实际业务规则，再写第六周迁移脚本；在新建隔离库上从 v0.1 导入样例、迁移、运行结构和业务验证，最后才考虑正式库。第五周的 ER 图是设计与核对材料，**不是迁移执行文件**。
