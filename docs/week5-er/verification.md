# 设计说明与验证记录

## 设计核对方法

以 [第二周数据字典](../week2-schema.md)识别业务对象和属性，以[实际建库脚本](../../sql/01_create_campus_store_database.sql)核对每个 PK、非空唯一键、可空唯一索引及 FK，再用[业务过程](../../sql/02_business_procedures.sql)判断哪些“必须参与”规则只在确认/结算时成立。图中 10 张实线实体对应 10 张表；`Member` 使用虚线且仅作第六周方案。`PurchaseItem` 和 `SaleItem` 分别把订单与商品的 M:N 联系拆成两条 1:N 联系。`InventoryLog.BusinessNo` 不是 FK，不画成订单与流水的直接外键联系。

## 如何在 SSMS 查看

连接与项目 README 相同的 SQL Server Express 实例，在 SSMS 中依次点“文件 → 打开 → 文件”，打开 [verification.sql](verification.sql)。工具栏数据库选择 `CampusStoreDB`，按 **F5**。脚本仅执行 `SELECT`，不会新增、删除或修改业务数据。结果按顺序显示表名、会员状态、外键列表、采购明细、销售明细、库存、库存流水，以及异常检测。如果正式库后来增加了业务记录，数量可能改变，判断关系时应以键和外键为准。

从空库演示时，先按[根 README](../../README.md)运行建库、业务过程和样例数据脚本。若只想核对第五周材料，不必重新建库。也可以在仓库根目录使用 PowerShell：

```powershell
$ServerInstance = '.\SQLEXPRESS'  # 改为 SSMS 对象资源管理器顶部显示的实例
sqlcmd -S $ServerInstance -E -No -b -f 65001 -i 'docs\week5-er\verification.sql'
```

## 预期观察与解释

| 检查项 | 导入固定样例后的预期 | 对应 ER 结论 |
| --- | --- | --- |
| 核心表与会员状态 | 10 张表；`Member` 显示“未实现（符合 v0.1）” | 会员框为拟议，不可当成当前表 |
| 外键清单 | 12 条 FK 列映射，包括分类自关联、库存 PK+FK、两个明细各两条 FK | 实线联系均可落到真实外码 |
| 主键与唯一索引 | 每张表有 PK；`PurchaseItem`、`SaleItem` 各有组合唯一键；`Product.Barcode` 是过滤唯一索引 | 区分主码、复合候选码和可空唯一限制 |
| `PO-DEMO-001` | `P0001` 数量 30、金额 66.00；`P0002` 数量 6、金额 18.00 | 一张采购单可含多商品；采购单总额 84.00 |
| `SO-DEMO-001` | `P0001` 数量 3、单价 3.50、明细额 10.50、实付 10.00 | 销售单、员工、商品通过外码可连接；无法判断会员身份 |
| 库存和流水 | `P0001` 库存 27，`P0002` 库存 6；可乐有采购 +30、销售 -3 流水 | 当前库存和历史变化分开保存 |
| 商品缺库存、完成单缺明细 | 正常样例应返回零行 | 零行只是当前数据满足业务规则，**不证明单靠 FK 就能永久保证规则** |

上表的数值来自仓库[样例数据](../../sql/03_sample_data.sql)和业务过程；这是脚本预期，不是对任意已修改正式库的断言。第六周如果实施会员或明细结构迁移，需要重画本图、更新规则表与这些验证预期。
