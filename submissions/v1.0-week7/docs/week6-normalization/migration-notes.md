# 迁移顺序、冲突处理与失败恢复

## 初始状态与两条路径

迁移只接受名称为 `CampusStoreDB_W6_*` 的完整 v0.1 副本：
InventoryLog 有 BusinessNo，尚无 PurchaseID/SaleID，已运行 baseline.sql。
三个 week6 SQL 都按当前连接数据库执行并检查名称，拒绝正式 CampusStoreDB。

需要保留展示数据时，先完整备份 v0.1，通过 SSMS 还原成不同库名及不同文件路径的副本，
在工具栏确认实例和副本后依次执行 baseline → migration → regression。
已还原的副本不再运行固定库名 01，也不重导 03；空库不能直接运行 migration。

自动路径使用 [Verify-Week6Migration.ps1](../../tests/Verify-Week6Migration.ps1)：
将冻结 01/02/view/role/03 中固定名称替换为本次随机库名，随后执行上述三个 week6 SQL。
这只是建立隔离测试初始数据；结构重构仍由 migration 在原有数据上完成。
自动测试结束会删除自己创建的临时库，正式库不会成为测试目标。

baseline 保存订单头、明细、商品销售、库存、完整流水及指标，共8张辅助表。
只能在迁移前采集，迁移后不能重新运行它覆盖对照基准。
采集是顺序执行，应暂停副本业务写入；不能用于在线繁忙库的一致性备份。

## 迁移动作

1. 验证库名、旧列、新列及基线存在；
2. 在事务中锁定来源，确认每条采购/销售流水唯一对应正确类型订单；盘点来源必须为空；
3. 增加两个可空订单 ID，按类型回填；
4. 校验回填，增加两个 FK、来源/方向 CHECK 及过滤索引；
5. 升级 ConfirmPurchase、CompleteSale 的写入列及员工职责检查；
6. 升级两类 StatusGuard，显式排除 NULL 或不可转换的过程标记；
7. 删除旧单号索引和 BusinessNo 实体列；
8. 创建兼容展示视图，用 LEFT JOIN 保留空来源盘点行；
9. 保留最小权限：完整流水视图仅管理员可读；
10. 写入 MigrationHistory，提交；事务内任一步异常整体回滚。

旧来源查询放在动态批次，避免重复执行时 SQL Server 提前编译已删除列，
使再次运行能明确报告“缺少旧列，可能已迁移”，而不是仅报列不存在。

## 数据冲突与恢复

- 来源不存在/无法唯一匹配，或盘点携带文本来源：错误 51613，在结构修改前拒绝。
  由组员核实业务凭据，修正副本来源或重新取得正确副本，再重新采集基线；不猜测订单、不丢弃流水。
- 方向、来源组合不合法，或过程定义不符合预期：约束/检查明确报错，事务撤销本次 DDL、回填、
  过程及触发器升级和权限调整。检查错误后在同一未迁移副本重试，无需删正式库。
- 成功后重复运行：错误 51610/51611，状态保持。要重演，从完整 v0.1 备份还原另一个副本。
- 成功迁移后回归失败：停止后续录入，不覆盖基线；保留输出和失败副本供定位。
  要恢复演示环境，用原 v0.1 备份还原成新的副本，不手工拼接已删除列或逆改过程。
- 连接中断：SQL Server 撤销未提交事务，重新连接后检查旧/新列及 MigrationHistory 判断状态；
  未确认提交前不能继续后续业务。

## 固定样例基线

| 指标 | 迁移前 | 迁移后预期 |
| --- | ---: | ---: |
| 分类 / 商品 / 员工 / 供应商 | 5 / 6 / 3 / 2 | 相同 |
| 采购单 / 采购明细 | 3 / 6 | 相同 |
| 销售单 / 销售明细 | 3 / 5 | 相同 |
| 库存 / 流水 | 6 / 11 | 相同 |
| 已收货采购总额 | 222.00 | 222.00 |
| 已完成销售原价总额 | 44.50 | 44.50 |

这只是冻结样例的基准。对含其他业务的备份，以 baseline 实际采集值为准；
回归对逐行语义和指标作比较，不把上述行数强套到其他合法数据。
真实执行输出、异常回滚和权限结果见[回归结果](regression-results.md)。
管理员读取应成功；浏览、采购、收银角色读取完整流水均应被拒绝。
