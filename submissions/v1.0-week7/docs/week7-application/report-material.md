# 第七周报告素材

## 设计思路

在第六周数据库上建立页面/API、业务、DAO和数据库四层应用。十张核心表保留，
仅增加应用账号和订单归属。员工职责、应用角色与数据库角色分别管理，
顾客草稿由配置的有效收银员受理，不将顾客ID当员工外键。
新增商品零库存；草稿不扣库存；完成订单保留；商品有历史则停用，无引用零库存才删除。
顾客仅本人订单，员工可查全店，数据库视图再次执行归属过滤。

## 实验过程

1. 准备Python虚拟环境、Flask、ODBC与浏览器依赖。
2. 从冻结v0.1建立随机W6副本，执行真实第六周迁移后改为独立W7库。
3. 部署账号/归属、视图/过程及受限身份，种子密码以带盐scrypt哈希保存。
4. 接通登录、商品CRUD、库存查询/预警、订单查询及草稿明细操作。
5. 统一错误响应和后端JSON日志，前端不暴露SQL及连接详情。
6. 用随机数据库做真实SQL集成测试，再启动独立临时服务完成浏览器验收。

## 调试与修正

真实测试发现UPDATE的WHERE主键条件还需SELECT权限，补充ProductID列权限，
未授db_owner或实际库存写权限。浏览器发现并发查询刷新永久会话Cookie会覆盖退出Cookie，
关闭只读响应刷新并补回归。ODBC会保留批次前导注释，影响旧迁移过程定义前缀检查，
准备工具仅去除发送批次的前导注释，原冻结SQL文件不改。

## 验证与总结

实际测试数、逐项结果、截图及原始输出见[验证记录](verification.md)。
重点覆盖认证/退出、三角色、输入/CSRF、SQL参数化、约束、订单归属、整单回滚、
数据库连接故障及日志定位。页面隐藏按钮不承担最终授权，业务层和数据库共同检查。
本周是登录和基础CRUD阶段，采购/结算/盘点界面在后续周次接入。
最终阶段报告须合并第5—6周设计迁移成果、后续流程和实际组员贡献；AI记录另行整理。
